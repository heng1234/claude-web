| 范围 | 问题 | 修复与证据 |
| --- | --- | --- |
| 会话隔离 | 新会话可能继承上一会话的模型服务、扩展；较晚返回的恢复请求可能覆盖新草稿 | 按会话保存前端选择，创建新会话时清理；恢复请求使用序号校验；4 项 Node 状态测试 |
| 消息队列 | 上传或排队期间切换会话后，消息可能读取当前可见会话的配置 | 将工作台选择与附件一起保存为提交快照，发送时按所属会话取值 |
| 浏览器模式 | 显式 Code 模式覆盖用户已经启用的浏览器开关 | 仅 Research / Review / Browser 强制相应浏览器策略；回归测试 |
| 模型与配置档 | 服务默认模型覆盖明确选择；部分后续请求丢失配置档默认值 | 保留显式模型和已有配置；兼容文本服务同样持久化会话执行配置 |
| 工作流输入 | 已指定只读配置档的步骤可能被输入中的 Slash Command 改成其他模式 | 工作流的内部步骤作为字面输入，不再次解析为用户快捷命令 |
| 任务恢复 | 再次打开 Workbench 数据存储会误把正在执行的任务标为中断 | 恢复只由服务启动流程执行，普通存储读取不修改任务状态 |
| 命令取消 | 只杀 shell 会遗留子进程，并可能卡住取消请求 | POSIX 工作流命令使用独立进程组，取消和超时统一清理；实际 shell 子进程测试 |
| 任务状态与报告 | 结束的任务仍能被改成取消，续跑可能保留失败步骤输出，报告步骤可能重复嵌套 | 校验状态，重做当前步骤前清理旧尝试，报告不递归包含报告步骤 |
| 安装资源 | ZIP 丢失脚本可执行位 | 保留常规可执行位，同时不保留特殊权限位；回归测试 |
| 本机接口 | 扩展上传等本机管理请求缺少单独的浏览器来源限制 | 工作台接口拒绝跨站 Fetch 和不匹配的 Origin；本机跨站请求测试 |
| 模型流式输出 | 流中途返回错误仍可能沿用之前的成功标志，清理异常可能残留忙状态 | 明确处理流式错误、失败标志与 finally 清理；模拟服务测试 |
| 表单 | 切换栏目、关闭或刷新可能丢弃未保存内容；请求期间可重复操作 | 未保存提示、提交反馈、提交时禁用相关控件；浏览器验证草稿保留与保存 |
| 异步 UI | 切换栏目时较旧的请求可能覆盖当前栏目，任务刷新可能打断详情 | 栏目请求序号、页面归属校验、详情打开时暂停刷新 |
| 权限显示 | 原生 default 无对应明确确认入口，可能被 UI 映射为项目默认/自动模式 | 增加「逐次确认」，配置档应用时同步 UI 和实际设置 |

| 导航与布局 | 标签页缺少方向键交互和面板关联 | 补充 tabpanel / aria-controls、单一焦点和方向键 / Home / End 切换 |
| 文案与缓存 | 动态权限名称可能固定为语言键名；浏览器重启后仍缓存旧工作台脚本 | 动态语言名称与加载完成刷新；JS/CSS 内容版本标识；8877 验证 |
