# CCW Desk 扩展与工作台

主入口：左侧主导航「工作模式」下方的「扩展与工作台」，普通聊天和工作模式均可直接打开。手机端先展开侧栏，点击后侧栏自动收起；顶部「更多工具 → 扩展与工作台」保留为备用入口。工作台在主内容区展示，左侧主导航保持可用，分类位于页面顶部，右上角可返回会话。打开工作台不会切换当前会话模式；聊天消息和输入草稿保留在原 DOM 中。工作模式输入区还提供快捷模式选择。

## 工作模式

| 模式 | 运行方式 | 行为 |
| --- | --- | --- |
| Chat | Claude CLI，或配置的兼容文本服务 | 普通文本对话 |
| Code | Claude Agent SDK；显式 legacy 配置可用 CLI | 文件、工具、测试和 Git |
| Research | Claude 原生 Code 运行时 | 研究、交叉核查与引用；禁止本地命令及文件修改 |
| Browser | Claude 原生 Code 运行时 | 浏览器检查与交互；禁止本地命令及文件修改，浏览器操作沿用审批 |
| Review | Claude 原生 Code 运行时 | 只读审查、文件定位与测试缺口分析 |
| Automation | Claude 原生 Code 运行时 | 作为工作流和长任务的配置入口；执行由工作流或现有 Agent Loop 启动 |

Research、Browser 和 Review 同时在工具列表和 SDK PreToolUse 中限制本地执行、修改文件和委派子代理。它们不是操作系统沙箱。插件 Hook 和 MCP 可以执行本地程序，需按来源选择组件。普通权限下有副作用的浏览器请求仍需确认。

快捷模式使用输入区的下拉菜单。未发出消息的 Code 草稿可以直接改选 Research、Browser、Review 等模式，保留已有输入和附件。已有会话改选模式时会先确认再新建；如果有待发送的附件、正在上传的文件或会话专属项目上下文，先处理这些内容再切换，避免丢失。只读模式显示相应权限说明，不覆盖 Code 的权限偏好。

Research 默认沿用现有工作区网页搜索设置；关闭时输入区提示「网页搜索未开启」，支持手动开启工作区搜索。选择 Research 本身不会自动联网。

切换 Chat / Code 会话类型时新建会话。已绑定模型服务的历史会话继续使用原服务。新建会话会清除上一个会话的服务和扩展选择；待发送队列会保留提交当时的工作台配置。权限中的「逐次确认」对应原生 `default`，与沿用项目默认策略的「默认模式」分开显示。

### 待发送与本轮结果

Code 队列记录提交时的模型设置、网页搜索、项目目录和 Git 分支，并在发送前重新检查项目及有效授权。分支、模型路由或授权发生冲突时保留队列并展示具体暂停原因；恢复原配置后可重新尝试，也可移除旧任务后按新设置提交。没有发送设置记录的旧队列项需重新提交。默认模型仍由实际运行时选择。

回复下方的「改动与验证」使用工作区实际记录的改动和验证命令结果。没有对应记录时显示「未验证」，不会把模型文字、终端自由执行或上一轮结果当作本轮工作区验证。通过入口运行的是当前工作目录的验证，不是重跑历史文件快照；手动验证关联最近一次主回合结果。

## 安装扩展

1. 打开「扩展目录」，预览内置代码审查或研究工具包；也可以在「扩展」中添加本地目录、ZIP、HTTPS Git 仓库。
2. Git 仓库可填写仓库内插件子目录，适用于一个仓库包含多个插件的情况。私有仓库沿用本机 Git 的 HTTPS 凭据，不在 URL 中填写 Token。
3. 预览名称、版本、组件和文件清单，然后安装。
4. 在扩展卡片中选择「配置范围」，设置全局、项目或会话范围，再选择具体组件。
5. MCP 和 Hooks 默认关闭。安装本身不会启用组件或执行安装脚本。
6. 新设置在下一轮加载；活跃 SDK 回合继续使用当前版本快照。

覆盖顺序：会话设置优先于项目，项目优先于全局。同一扩展在较具体范围中禁用，会覆盖上层的启用设置。配置档中的扩展列表筛选当前已启用的扩展，不会越过作用范围自动授权。

支持两种清单：

```text
my-plugin/
├── ccw-plugin.json                 # 或 .claude-plugin/plugin.json
├── skills/my-skill/SKILL.md
├── skills/my-skill/scripts/        # 与技能一起保留
├── skills/my-skill/references/
├── agents/reviewer.md
├── commands/review.md
├── .mcp.json
├── hooks/hooks.json
└── workflows/checks.json
```

最小 `ccw-plugin.json`：

```json
{
  "id": "my-plugin",
  "name": "我的开发工具包",
  "version": "1.0.0",
  "description": "代码审查和提交前检查"
}
```

标准 Claude Code 插件使用 `.claude-plugin/plugin.json` 的 `name` 作为标识。Skills、Agents、Commands 使用标准同名目录；自定义目录布局需先调整为标准目录，才能逐组件启停。

扩展文件会复制到应用数据目录的 `workbench/packages/`，支持最多 32 MB、2000 个文件。ZIP 不允许路径穿越或符号链接。更新保留旧版本，回滚不删除活跃回合正在使用的目录；卸载移除安装记录和范围设置，快照保留供已有回合完成。

「检查更新」重新拉取安装来源，显示预览，由用户决定是否安装新版。上传的 ZIP 需要手动上传新版。

## 扩展目录与评分

内置目录可离线使用。自定义来源使用 HTTPS JSON，支持以下格式：

```json
{
  "name": "团队扩展",
  "plugins": [
    {
      "name": "team-review",
      "display_name": "团队审查工具包",
      "description": "统一代码审查规范",
      "source": "https://github.com/example/team-tools.git",
      "subdir": "plugins/team-review"
    }
  ]
}
```

也支持 `source: {"source": "github", "repo": "example/team-tools"}`。每项来源指向独立 HTTPS Git 仓库，可用 `subdir` 指定子目录。评分仅保存于本机，不是公共市场评分。

## 配置档与快捷命令

配置档可以保存模式、项目、模型、推理强度、权限、系统提示词、模型服务和扩展组合。应用时新建会话，并在后端保留该会话的执行配置。

快捷命令包含上述配置以及 Prompt。`{{input}}` 会替换为用户输入；未包含占位符时，将输入追加在 Prompt 后面。

- 在「快捷命令」中点击「应用」，然后输入任务。
- 在输入框键入 `/`，可发现自己的工作台命令。选中时应用其配置并等待任务输入。
- 也可直接发送 `/命令标识 参数`；如果命令要求另一种会话类型，先新建相应会话。
- 已启用插件的原生命令以 `/插件标识:命令名` 显示，由 Claude Code 原生执行。

## 工作流与任务中心

第一版采用顺序步骤，以 JSON 定义，可复用配置档：

```json
[
  {"type": "prompt", "name": "分析任务", "value": "分析以下任务：{{input}}"},
  {"type": "command", "name": "运行测试", "value": "python3 -m unittest discover -s tests", "timeout": 120},
  {"type": "report", "name": "生成报告"}
]
```

每个工作流最多 30 步，最多同时执行 2 个工作流。每次运行使用独立会话。命令步骤先展示原始命令，只有在任务中心明确批准后才执行。

任务中心显示排队、执行、命令审批、原生工具审批、浏览器证据等待、完成、失败与停止状态。工作流本地命令在 POSIX 系统中使用独立进程组，取消和超时会终止子进程。可以打开任务会话处理工具审批，停止运行，查看逐步骤结果，以及下载 Markdown 报告。失败或服务重启后可从当前步骤继续，已成功步骤不重复执行。

浏览器验收步骤使用已有验收配方和证据注册表：

```json
{"type": "browser_validation", "name": "浏览器验收", "value": "拥有配方的会话ID/配方ID", "timeout": 300}
```

该步骤创建待执行 Run，并等待外部浏览器执行器在原会话的验收面板回传证据。只有注册表确认 `passed` 且具有证据才继续；无法执行、失败或超时不会当作通过。它不会凭模型的口头结论伪造浏览器验收结果。

已启用扩展中的 `workflows/*.json` 会显示在工作流列表，可直接运行或另存为个人工作流。

## 模型服务与路由

- **OpenAI 兼容**：填写服务的 API Base URL（含 `/v1`，如该服务需要）、模型 ID 和可选 Key。用于 Chat 文本流式对话，支持本地无 Key 服务；当前不支持该协议的工具调用和图片。
- **Anthropic 兼容**：填写服务根地址、模型 ID 和 Key。由 Claude 原生运行时通过独立环境连接，可用于代码与工具。实际工具能力取决于服务的 Anthropic 兼容程度，不会回退到其他服务重放任务。
- HTTPS 用于远程服务；HTTP 只允许 localhost / 回环地址。
- 每种工作模式可以指定默认模型和服务；配置档也可以覆盖。代码模式不能路由到只提供 OpenAI 文本协议的服务。
- API Key 使用现有 SecretStore 加密，只向运行进程或所配置的服务提供明文；界面和导出内容不返回 Key。
- 更新 Key 保留服务标识；已有会话会继续使用原服务。仍被会话或配置引用的服务禁止删除。

「测试推理」会向服务默认模型发送一次最多 16 输出 Token 的短推理请求；「测试所选模型」使用路由表单中的模型 ID。两者会验证实际文本响应，不以模型目录能访问作为推理成功。真实服务可能收取少量费用。模型 ID 优先采用配置档、路由或服务配置，聊天框残留的 Claude 别名不会发给第三方服务。路由变更仅对新会话生效，已绑定兼容服务的会话保留其服务和模型；原生会话也不会被新的默认路由改换服务。追问建议、标题生成和 Chat 压缩也沿用同一绑定，失败时不切换到默认 CLI。

已完成本机 HTTP 服务端到端验证，以及真实安装 Agent SDK 接入模拟 Anthropic 服务并执行 Read 工具的验证。尚未使用真实供应商 Key 或收费模型验证所有厂商。

## 导入、导出和数据

「导入 / 导出」支持 JSON 和 ZIP，包含配置档、快捷命令、工作流和扩展来源。ZIP 内含 `ccw-workspace.json`。选择文件只预览，列出将新增、将覆盖和内容相同的配置。点击「确认导入」才一次性写入变动项；取消不会写入。如果预览后目标配置有变化，需要重新预览确认。

凭据、模型服务、已安装扩展程序内容、MCP 环境变量和运行历史不导出。目标电脑按来源重新安装扩展并配置服务；这避免把本机密钥带给团队。配置 Prompt 中手动填写的敏感文字属于用户文档，分享前需自行检查。

数据位于应用数据目录下的 `workbench/`，随 `CLAUDE_WEB_DATA_DIR` 隔离。数据库为 `workbench.sqlite3`；扩展配置由本机管理接口维护，不会写入用户现有的 `.claude/settings.json`。

工作台与会话之间切换时保留未保存的表单，重新打开仍可继续编辑；切换工作台内部栏目或刷新页面时提示未保存内容。移动端提供主导航按钮；工作台栏目从下拉列表直接切换，桌面端仍用横向标签。扩展组合使用勾选项。扩展管理接口会校验浏览器来源，拒绝跨站页面向本机提交安装和任务请求。
