Claude Code GUI 竞品对比与排期

claude-web · opcode · claudecodeui · jetbrains-cc-gui

核心判断：三个竞品中只有 jetbrains-cc-gui 有真正的模式创新——它把「每条消息自动携带用户正在看的代码」做成默认行为，回复质量的提升是肉眼可见的。 opcode 和 claudecodeui 本质是功能清单型项目（会话浏览器、用量面板、配置编辑器），能抄但抄了不改变产品档次。

因此排期原则：上下文自动注入 > 配置面板堆叠。已砍掉 Hooks 编辑器、Command Palette、时间线可视化、多 Provider、插件系统、语音输入等 6 项低 ROI 需求。

排期

7 项，按「改变产品档次的程度」而非「工程量」排序。周数为单人开发估算。

v2.3 上下文自动化 —— 让用户不再手动粘贴代码
2 周
1. @ 提及系统（文件 / 终端 / 运行进程） jetbrainsclaudecodeui 约 3 天
输入 @ 弹出候选列表，可引用项目文件、当前终端最近输出、正在运行的进程。jetbrains 把终端和 Run 配置也做成可 @ 引用的伪文件，这是两个 web 竞品都没有的思路——「把当前正在发生的事附加给 AI」。
实现
  • 前端：输入框 @ 触发 popup + 模糊过滤（复用现有 code-tree 接口）
  • 后端：新增 GET /api/sessions/{id}/mentionable，返回文件树 + 活跃终端 + 运行进程
  • 选中后插入 @path/to/file 标记，发送前后端展开为真实内容
2. 当前文件自动注入（可开关） jetbrains 约 2 天
代码检查器里打开的文件、选中的行号范围，默认作为上下文附加到每条消息。这是 jetbrains 插件回复质量高的根本原因，不是模型差异。做成可开关避免长文件浪费 token。
实现
  • 前端记录检查器当前文件 + 选中行范围，随 ChatRequest 一起发送
  • 后端构造 <ide_context> 段落，附加到 system prompt（复用 memories 注入路径）
  • 输入框旁放开关 + token 预估提示；超过阈值只注入选中片段
3. SSE 断线重连重放 claudecodeui 约 2 天
移动端 OTP 远程访问是我们的独有能力，但网络一断 SSE 就丢事件，长任务等于白跑。SSE 协议原生支持 Last-Event-ID 重连，不必换 WebSocket。这是可靠性欠债，不是新功能。
实现
  • 每个 SSE 事件加自增 id: 字段
  • 服务端每会话维护 deque(maxlen=5000) 环形缓冲，5 分钟过期
  • 重连时读 Last-Event-ID 请求头，补发缺失区间
v2.4 工作流复用与审批体验
3 周
4. 自定义 Agent 库 + 会话模板 opcodejetbrains 约 1 周
opcode 的 Agent 定义（名称/图标/系统提示/模型/权限/hooks，导出 .json 分享）+ jetbrains 的会话模板（模型/权限模式/cwd 存成命名快照）合起来就是用户自定义的可复用工作流。CLI 做不到，且是团队版 Agent 市场的地基。
实现
  • 表 agent_templates：name / icon / system_prompt / model / permission_mode / default_task / cwd
  • CRUD + 克隆 + 导出导入 .json
  • 新建会话时「从模板创建」一键填充；system_prompt 走现有 append-system-prompt 通道
5. Diff 可编辑后接受 jetbrains 约 4 天
现在权限审批只能全盘接受或拒绝。jetbrains 让右侧 diff 可编辑，用户微调 AI 的改动后再应用——消除了「大体对但有一处不对，只能拒绝重来」的困境。三个竞品里只有它做了。
实现
  • 权限预览接口已有（preview-change），前端右栏换成可编辑编辑器
  • 新增「接受修改版」：把编辑后内容作为审批结果回传，覆盖原 tool 入参
  • 需在 bridge 层支持带修改内容的 approve
6. AI 生成 Commit Message jetbrains 约 2 天
读 staged diff，一次性调用（maxTurns=1，不建会话、不留历史），token 流式写入输入框。工程量很小但演示效果好，且天天用得上。三个竞品里只有 jetbrains 有任何 VCS 写入集成。
实现
  • Git 面板加按钮 → POST /api/git/commit-message
  • 后端读 staged diff，走 bridge 一次性 query（不落 session 历史）
  • SSE 流式回传，前端逐 token 写入 message 输入框
v2.5 配置可视化与成本透明
1.5 周
7. CLAUDE.md 与 Slash Commands 管理 opcodeclaudecodeui 约 4 天
CLAUDE.md 是 Claude Code 用户改得最频繁的文件，现在必须跳编辑器。递归扫描项目内所有 CLAUDE.md + 扫描 .claude/commands/*.md（解析 YAML frontmatter）做成面板即可。
注：opcode 的 Hooks 可视化编辑器已砍——实际改动频率远低于 CLAUDE.md，投入产出不划算。
实现
  • 递归查找 CLAUDE.md（user / project 双作用域），markdown 编辑器 + 保存
  • 扫描 ~/.claude/commands/ 与 .claude/commands/，解析 frontmatter 的 description / allowed-tools
8. 全局用量/成本仪表盘 opcode 约 3 天
我们已有单轮 usage 记录，缺的是跨会话聚合视图。opcode 的做法可直接照搬：遍历 ~/.claude/projects/**/*.jsonl，按 message.id + requestId 去重，按模型/日期/项目聚合，缺 costUSD 时用价格表兜底。团队版预算管控的前置件。
实现
  • 复用现有 session_usage 表做主数据源，JSONL 扫描补齐 CLI 原生会话
  • 去重键 message.id + requestId；价格表作为 costUSD 缺失时的兜底
  • 面板：总览 + 按模型 / 按日期 / 按项目，支持日期范围过滤

已砍需求

看过但决定不做，记录原因避免以后重复讨论。

需求来源不做的原因
Hooks 可视化编辑器opcode纯配置面板。用户改 hooks 的频率远低于改 CLAUDE.md，同样工程量下优先级明显更低。
Command Palette（Cmd+K）claudecodeuinice-to-have 而非痛点。当前侧栏导航已够用，浏览器本身也有搜索。
时间线可视化 + 分支opcode已有 git checkpoint + rewind。做树形可视化工程量大，不如先把现有 rewind 的交互打磨顺。
多 Provider（Codex/Grok/Kimi）jetbrains / claudecodeui架构改动大，且会模糊「Claude Code 的 GUI」这个定位。
插件系统claudecodeui26k 行单文件前端下不现实。要做得先组件化重构，那是独立的大工程。
语音输入 / TTSclaudecodeui依赖外部 STT 服务。移动端资源应优先投给断线重连这类可靠性问题。
PSI 语义索引jetbrains依赖宿主 IDE 的符号索引，web 应用没有等价物。除非未来接 LSP，否则无法复刻。
直连 API 纯对话模式四家都没有确实是空白，但不是 Claude Code GUI 的核心场景。现有 CLI 聊天模式够用，留到 v3.0 再评估。

我们已有的护城河

三个竞品都没有的能力，做新功能时注意不要削弱这些。

Agent Loop 自动多轮
20 轮上限 + token 预算 + 测试命令验证。唯一支持无人值守连续执行的 GUI。
移动端 OTP 远程访问
访问码 / TOTP + 路径白名单。其他三家全是本地 only。
Chrome 浏览器扩展
侧栏形态，只读 / 完整双模式。唯一能嵌进浏览器工作流的方案。
Memories + Pinned Docs
跨会话持久记忆 + 会话级固定文档注入。
Prompt 优化器
样本采集 + 规则管理 + 重写。系统化的 prompt engineering 工具。
代码块在线执行
Run 按钮直接跑 Python/JS，不必手动复制到终端。
服务端消息队列
DB 持久化排队 + 顺序派发。claudecodeui 只有客户端 localStorage。
浏览器自动化验证
Recipe 驱动的前端改动验证与证据留存。
